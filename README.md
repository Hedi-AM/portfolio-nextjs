# portfolio-nextjs

Portfolio Next.js of Hedi Ben Abdelmoumen, generated by the Backstage template `portfolio-nextjs-template`.

## Architecture

Backstage (Fedora) -> Scaffolder -> GitHub repo -> GitHub Actions (build + push image to Docker Hub) -> self-hosted runner on the VM (docker compose up + health check) -> http://192.168.122.180:3005

## Content

- `app/` Next.js app (App Router), `app/api/health` health endpoint (returns the deployed version)
- `Dockerfile` multi-stage build (standalone output), `.dockerignore`, `docker-compose.yml`
- `.github/workflows/ci-cd.yml` pipeline: build, Docker image, push, deploy, health check
- `evolution/` v2 version of the app (Certifications, Projets DevOps & Cloud, Dark Mode, updated title)
- `catalog-info.yaml` Backstage catalog registration

## Pipeline

1. Trigger: first push (v1) or `workflow_dispatch` launched from Backstage (template `portfolio-redeploy`).
2. Optional: apply `evolution/` over `app/` and commit (done by the pipeline, no manual git).
3. Build image `hediam/portfolio-nextjs:<version>` and push it with `latest` to Docker Hub.
4. Deploy on the VM runner (label `portfolio-vm`) with `docker compose up -d --pull always`.
5. Health check on `/api/health`, which must report the new version.

## Secrets

`DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` are created in the repo by Backstage from the template form.

## Ports

The spec expects `http://localhost:3000`. Docker runs only inside the VM, and VM port 3000 is already used by another project, so the container port 3000 is published on VM port 3005: `http://192.168.122.180:3005`.

## Versioning

v1 on creation, then the version typed in the Backstage redeploy form (v2, v1.1, ...). `latest` always points to the last build.
